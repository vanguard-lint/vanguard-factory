# Quản lý secret (vận hành)

Mô hình secret: [Secret & quyền](/docs/architecture/phan-quyen-bao-mat/secret-va-quyen).
Trang này là **thủ tục vận hành** thực tế.

## Nơi lưu hợp lệ — và không hợp lệ

| Nơi | Hợp lệ? |
|---|---|
| Vault trung tâm của harness | ✅ nơi lưu chính |
| Biến môi trường trên host (script chạy ngoài repo) | ✅ cho token dịch vụ (`WORKLOOP_TOKEN`, `DSH_TOKEN`) |
| Factory repo / repo mã nguồn | ❌ tuyệt đối không — chỉ tên ref |
| Docs, wiki, chat, ticket | ❌ không bao giờ |
| File `.env` nằm trong repo | ❌ — giữ ngoài repo, thêm vào `.gitignore` |

## Vòng đời token

```
SINH ──▶ CẤP (qua env/vault, đúng phạm vi tenant) ──▶ SỬ DỤNG ──▶ LUÂN CHUYỂN định kỳ ──▶ THU HỒI
                                                                     (đổi sau restart của DSH)
```

1. **Sinh** — tạo trong vault/dịch vụ nguồn; đặt tên ref theo quy ước `<muc-dich>-<tenant>`.
2. **Cấp** — gán vào env của thành phần cần dùng; không lan truyền qua nhiều nơi hơn cần.
3. **Luân chuyển** — **DSH đổi token sau mỗi restart**: bắt buộc cập nhật `DSH_TOKEN` và khởi động
   lại backend ([Xử cố](/docs/user-guides/workloop-dieu-phoi/xu-co)). Token dịch vụ ngoài luân
   chuyển theo chính sách của dịch vụ.
4. **Thu hồi** — khi thành viên rời nhóm/token nghi lộ: thu hồi ở dịch vụ nguồn, sinh token mới,
   cập nhật env/vault, kiểm tra log truy cập.

## Sự cố lộ secret — quy trình khẩn

1. Thu hồi ngay ở dịch vụ nguồn (không đợi luân chuyển định kỳ).
2. Quét lịch sử Git xem secret đã bị commit chưa; nếu có → xoá khỏi lịch sử + đánh giá phạm vi lộ.
3. Đổi mọi token cùng phạm vi; ghi nhận sự kiện vào log vận hành.
4. Rà lại quy trình cấp để không tái diễn.

## Kết quả đúng phải thấy

Không có giá trị secret nào tìm thấy bằng lệnh quét đơn giản trong các repo:

```bash
grep -rE "(token|password|secret)\s*[:=]\s*['\"][^'\"]{8,}" <repo>/ --include="*.md" --include="*.yaml"
# Chỉ khớp placeholder — không có giá trị thật.
```
