# Model, plugin và secret

Chuẩn bị năng lực cho task trước khi chạy workflow. Một phiên chat DSH dùng được model hoặc
tool chưa chứng minh node Workloop có cùng cấu hình.

## Chọn model

Workloop đọc provider và model từ factory cùng override của node. Profile thực thi riêng của
ADLC có thể pin một route cố định. Lựa chọn model đang hiển thị trong phiên chat không ghi
đè các cấu hình đó.

Ghi lại provider, model ID và profile trước smoke test. Sau khi chạy, kiểm tra metadata phiên
và usage do runtime trả về. Giữ ID provider/model của môi trường đang dùng; các tên trong
ví dụ tài liệu cần được thay bằng route đã cấu hình.

Nếu model không khả dụng, kiểm tra route và credential của provider. Chỉ đổi model sau khi
cập nhật cấu hình task/profile theo quy trình của nhóm. Profile đã pin model phải báo lỗi
khi route đó không dùng được, thay vì tự chuyển model.

## Kiểm tra plugin

| Bước | Cần xác nhận |
|---|---|
| Cài package | Đúng package, version và entry point |
| Nạp vào profile | Loader đọc được plugin và service phụ thuộc |
| Cấp tool cho agent | Tool xuất hiện trong runtime của phiên |
| Gọi backend | Kết nối, credential và quyền đáp ứng task |

Plugin Hub quản lý package; deployment còn có thể nạp plugin qua `plugins/patch.yml`.
Entry mới của file patch phải nằm trong khối `insert`. Row đặt sai chỗ có thể bị hiểu là
sửa entry cũ, khiến plugin không được nạp dù container vẫn khởi động.

Sau khi thêm plugin, kiểm tra inventory/loader và gọi chức năng đọc trạng thái nếu có.
Với TestForge, dùng `testforge_health` từ chính Harness. Tránh tạo job ghi chỉ để kiểm tra
kết nối.

## Cấp credential

Trong DSH, mở **Settings → Secrets**, thêm tên ref và giá trị do admin cấp. Plugin `vai-secrets`
trả danh sách tên, không xuất ngược giá trị qua API liệt kê. Kiểm tra bằng chức năng sử dụng
credential thay vì yêu cầu agent in credential.

| Credential | Bên sử dụng | Nơi cấu hình |
|---|---|---|
| `DSH_TOKEN` | Gateway Workloop hoặc Python SDK | Môi trường của bên gọi DSH |
| API key của model | Provider trên Harness | Vault hoặc cấu hình credential của provider |
| `TESTFORGE_BROKER_TOKEN` | Plugin TestForge | Vault/runtime plugin |
| `VAI_SANDBOX_TOKEN` | Plugin Sandbox | Vault/runtime plugin |
| `AGENT_MEMORY_API_KEY` | Broker TestForge gọi Cognee Adapter | Môi trường broker, nếu dùng Adapter HTTP |
| `ADLC_HARNESS_API_TOKEN` | ADLC gọi execution hub REST | Cấu hình phía ADLC và phía hub |
| `ADLC_HARNESS_CALLBACK_SECRET` | Hub ký, ADLC kiểm tra callback | Hai phía đường callback |

`DSH_TOKEN` đăng nhập Web UI/SDK và bearer của execution hub là hai loại credential riêng.
Tên ref trong brief hoặc YAML chỉ trỏ tới cấu hình; nó không chuyển secret giữa Workloop,
Harness và broker.

## Áp dụng thay đổi

| Thay đổi | Cách áp dụng trong deployment tham chiếu |
|---|---|
| Vault mà plugin resolve theo từng lời gọi | Có hiệu lực ở lời gọi tiếp theo |
| Code plugin hoặc `plugins/patch.yml` | Nạp lại runtime/container sau khi kiểm tra |
| Dockerfile hoặc package trong image | Build image rồi tạo container từ image mới |
| Env/volume trong Compose | Tạo lại service để container nhận cấu hình |
| Branding đọc theo request | Reload giao diện |

Plugin khác có thể cache cấu hình. Đọc cơ chế của đúng plugin trước khi kết luận cần restart.
Đổi vault Harness cũng không làm env của TestForge broker tự nạp lại.

Profile dùng `plugin_lock` kiểm tra cả version và digest của bytes cài đặt. Nếu không khớp,
sửa bản cài hoặc phát hành version mới. Giữ lock của session và recipe đã phát hành để đọc
lại lịch sử; xem [viết plugin](/docs/developer-docs/viet-plugin).

## Kết quả đúng phải thấy

Node dùng đúng provider/model, inventory nhận đúng plugin và tool gọi được backend từ
Harness. Report không chứa secret. Sau đổi cấu hình, chạy task nhỏ của đúng profile trước
khi dùng lại workflow sản phẩm.
