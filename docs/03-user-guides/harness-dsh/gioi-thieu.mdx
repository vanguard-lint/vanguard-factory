# Sử dụng Harness (DSH)

Harness (DSH) là nơi agent thực thi task: nhận brief, dùng model/công cụ, làm việc trong
workspace và trả report. Với công việc theo workflow, điểm bắt đầu là **dashboard Workloop**.
Bạn chọn workflow, theo dõi ở **Runs** và xử lý các điểm cần người quyết định ở **Duyệt**.

Giao diện DSH dùng để quản trị model, plugin, secret và kiểm tra chi tiết phiên. Kiến trúc:
[Tầng 3 · Harness](/docs/architecture/tang-3-harness/tong-quan-harness).

:::note[Chọn đúng cách tích hợp]

Workloop dùng gateway DSH và TaskLoop contract. Mã ADLC còn có execution hub REST, contract
đã duyệt và vòng lặp kiểm chứng riêng. Các profile này dùng API/credential khác nhau và
không tự xuất hiện trong Workloop khi cài DSH. Đối chiếu
[giao diện Harness](/docs/reference/harness-interfaces) trước khi dùng một profile mới.

:::

## Khái niệm chính

| Khái niệm | Ý nghĩa |
|---|---|
| Workloop job | Một lần chạy DAG, có các node và lịch sử sự kiện riêng |
| Session | Phiên agent của task/attempt; dùng session ID để tra cứu trong DSH |
| Workspace | Không gian tệp trên Harness, có thể khác filesystem máy người dùng |
| TaskLoop contract | File theo dõi tiến độ; gateway đọc để xác định trạng thái task |
| Plugin | Gói đăng ký năng lực; có thể gọi backend như TestForge broker |
| Vault | Nơi runtime lấy secret theo tên ref |
| HITL | Điểm cần con người quyết định trong luồng đang chạy |

## Điểm vào giao diện

| Ở đâu | Khi nào dùng |
|---|---|
| Workloop → **Factory / Workloop** | Kiểm tra workflow đã sync và cấu trúc DAG |
| Workloop → **Runs** | Xem node, report, attempt và session ID |
| Workloop → **Duyệt** | Đọc ngữ cảnh rồi duyệt, yêu cầu sửa hoặc từ chối |
| DSH → phiên agent tương ứng | Đọc tool call, lỗi model hoặc nội dung phiên để chẩn đoán |
| DSH → **Plugins / Settings → Secrets** | Quản trị plugin và credential |

Tên mục quản trị DSH có thể khác theo bản triển khai; dùng URL do admin cấp, giữ nguyên token
trong công cụ quản lý secret. Không dán token vào brief, ảnh chụp hoặc link chia sẻ.

## Kết quả đúng phải thấy

Workloop thấy workflow và SHA sau sync. Workflow thử một node chạy qua gateway DSH, dùng
đúng model/provider và trả report có session ID, trạng thái contract cùng đầu ra đọc được.
Với TestForge, report giữ thêm mã job broker và bằng chứng của đúng SUT/suite.

Health đạt chỉ xác nhận một phần kết nối. Để bàn giao task, cần đọc đầu ra và hoàn thành
review theo workflow.
