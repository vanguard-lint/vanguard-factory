# Secret & quyền — mô hình

## Nguyên tắc gốc

> Secret không bao giờ nằm trong factory repo, trong spec, trong brief hay trong docs —
> **chỉ có tên ref** trỏ tới vault.

```
Agent / workflow ──cần secret──▶ hỏi qua tên ref ──▶ VAULT ──▶ trả giá trị đúng lúc, đúng phạm vi
                                   (không có giá trị)   (giá trị sống ở đây)
```

## Thành phần

| Thành phần | Mô tả |
|---|---|
| **Central Vault** | Nơi lưu giá trị secret duy nhất của harness; ingress kiểm soát ai được đọc ref nào |
| **Token ref** | Tên đại diện (ví dụ token truy cập dịch vụ ngoài) — spec/brief chỉ được nhắc tên ref |
| **Tenant** | Mỗi tenant (sản phẩm) có factory repo + bộ ref riêng; dữ liệu tenant cách ly nhau |
| **Token API nội bộ** | Bearer token bảo vệ backend (`WORKLOOP_TOKEN`) và điều khiển harness (`DSH_TOKEN`) — cấp qua biến môi trường trên host |
| **Giới hạn tài nguyên** | Mỗi phiên sandbox có hạn ngạch (CPU/RAM/thời gian) cấu hình ở broker |

## Phân quyền theo vai

- **Agent** — chỉ quyền cần cho task hiện tại trong sandbox; không quyền merge, không quyền đọc
  vault ngoài ref được cấp.
- **Orchestrator** — quyền điều phối (tạo run, dừng/resume), không quyền thay spec đã đóng băng.
- **Người duyệt** — quyền duyệt gate và merge PR; duyệt hợp lệ phải ghi danh tính người duyệt.
- **Admin** — quản lý secret, webhook, cấu hình tenant; thao tác được audit.
